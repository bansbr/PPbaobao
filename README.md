# 小芽日记 · 宝宝成长记录系统

本地自托管的宝宝成长档案：多宝宝、多照护者、两级权限，数据全部存在自己的 SQLite 文件里，不依赖云服务、外部 CDN 或任何第三方账号。公开注册已关闭，账号由系统管理员统一创建。

> 本文档对应当前代码版本（`1.0.0`），涵盖部署、初始配置、逐页使用、备份迁移与运维操作。

## 1. 功能总览

| 页面 | 覆盖内容 |
| --- | --- |
| 🏠 今日概览 | 当日喂养次数与奶量、睡眠夜醒、大小便、最近生长测量、童言快照、成长速览、接种提醒；四个快捷录入按钮 |
| 🍼 喂养记录 | 母乳亲喂 / 母乳瓶喂 / 配方奶 / 辅食 / 喝水，记录奶量、亲喂时长、喂哺侧、辅食名称；勾选「首次引入过敏原」会自动写入独立的**过敏原引入台账**（反应等级与描述） |
| 😴 睡眠记录 | 夜间睡眠 / 白天小睡 / 夜醒；填起止时间自动算时长，记录夜醒次数与睡眠质量 |
| 🚽 大小便 | 尿量、颜色、性状、便量，支持**拍照上传**（自动压缩后存入本机数据库，随备份一起带走）；灰白 / 带血丝自动标「建议关注」 |
| 🌕 黄疸观察 | 经皮胆红素值、黄染部位、程度、消退状态，按已登记数值给出升降趋势 |
| 📈 生长曲线 | 体重 / 身长身高 / 头围，叠加 **WHO 0–5 岁官方 LMS 标准** P3/P15/P50/P85/P97 五条百分位线；越界或跨线下移自动标红，数据表同步显示百分位 |
| ⭐ 发育里程碑 | 13 项预设里程碑按月龄对照参考窗口（窗口内 / 偏早 / 偏晚 / 超窗口）；另有**自定义里程碑**，可自由记录对照表之外的成长瞬间（名称、达成日期、备注，可增删改） |
| 🩺 医疗档案 | 四个页签：接种表（国家免疫规划 + 常见自费苗，逐剂次登记）、儿保体检、用药记录、过敏史 |
| 💬 童言童语 | **原话 + 当时语境** + 时间 + 说话人 + 标签，卡片流展示并支持搜索，导出时完整保留 |
| ⚙️ 设置与协作 | 宝宝档案、主题色、照护者名单、用户管理（管理员）、账号安全、数据导出与备份、删除宝宝档案 |
| 👥 用户管理 | 仅系统管理员可见：新增 / 编辑 / 删除账号、系统权限、启停、重置密码、逐个宝宝分配档案角色 |

界面为 Claymorphism 风格：超大圆角、内外组合阴影、糖果色渐变、弹簧缓动，浅色主题、移动端自适应，支持 5 套主题配色。

**数据模型**：`users` / `sessions` / `babies` / `baby_members` 四张基础表 + **12 类记录表**（喂养、睡眠、大小便、黄疸、生长、里程碑、接种、儿保、用药、过敏史、过敏原引入、童言），共 16 张表。所有记录都带记录人，多人协作可追溯。

## 2. 技术栈

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 后端 | Node.js 22 + Express 4 | 单进程 REST API，同时托管静态页面 |
| 数据库 | **Node 22 内置 `node:sqlite`** | 真 SQLite 文件（WAL 模式），**无需任何原生编译工具链** |
| 前端 | 原生 HTML / CSS / ES Modules | 零构建、零 CDN，源码即运行产物 |
| 图表 | 自绘 SVG | 离线可用，不引第三方图表库 |
| 认证 | scrypt 加盐 + HttpOnly Cookie 会话 | 会话存数据库，有效期 30 天；公开注册已关闭；停用 / 改密即时踢下线 |
| 部署 | Docker + docker-compose | 命名卷持久化数据库，容器自带健康检查 |

## 3. 部署指南

### 3.1 环境要求

- **Node.js 22.5 以上、23 以下**（`node -v` 检查）；或任意可运行 Docker 的环境。
- 约 30 MB 磁盘空间；数据库随记录增长（含照片时增长更快）。
- 无需数据库服务、无需 Redis、无需外网（WHO 标准数据已内置在 `src/data/who-lms.json`）。

### 3.2 本机启动

```bash
cd "下载好的文件夹目录内"
npm install
npm start
```

打开 <http://localhost:3000>。首次启动会自动建库、建表、创建初始系统管理员，并打印启动信息（**日志不打印密码**）。

开发模式（文件变更自动重启）：`npm run dev`

改端口：

```bash
PORT=3100 npm start          # macOS / Linux
set PORT=3100 && npm start   # Windows CMD
$env:PORT=3100; npm start    # Windows PowerShell
```

Windows 上若要常驻后台，可用「任务计划程序」或 `pm2` / `nssm` 之类工具把 `npm start` 注册为服务；也可用下面的 Docker 方式。

### 3.3 初始管理员与首次登录

```
用户名：admin
密码：  123456
```

> ⚠️ 这是 `src/bootstrap.js` 里的默认值，**仅在「数据库里一个管理员都没有」时由首次启动创建**。登录后请立刻到「设置与协作 → 账号安全」修改密码；局域网内其他人也能打开这个页面。想一开始就用自己的强密码，在**首次启动前**设置 `ADMIN_PASSWORD` 环境变量即可。
>
> 管理员登录后顶部会出现全站「修改初始密码」安全横幅，改掉默认密码后自动消失。登录页面本身不展示任何账号提示或凭据说明。

**首次使用的推荐顺序**：改管理员密码 → 在「用户管理」为家人建号并分配权限 → 创建宝宝档案 → 开始记录。详见 [4.1](#41-第一次使用的推荐顺序)。

### 3.4 Docker 部署

```bash
docker compose up -d --build
# 访问 http://<NAS 或主机 IP>:3000
docker compose logs -f
docker compose down          # 不会删除数据卷
```

要点：

- 数据库在容器内 `/app/data/baby-journal.db`，由命名卷 `baby-data` 持久化；**升级镜像、重建容器都不会丢数据**。
- 想在主机上直接看到数据库文件，把 compose 的卷改成 `- ./data:/app/data`（先 `mkdir data`）。WHO 标准数据在 `src/data/`，不在数据卷里，**绑定挂载空目录也不会覆盖它**。
- 改端口：改 `ports` 左侧（如 `"3100:3000"`），右侧与 `PORT` 保持一致。
- 首次启动想自定义初始管理员，在 `environment` 中取消注释并设置 `ADMIN_USERNAME` / `ADMIN_PASSWORD`。
- 容器带健康检查（`/api/health`），`TZ=Asia/Shanghai` 已预设。
- 基础镜像与 npm 源可通过 `NODE_IMAGE` / `NPM_REGISTRY` 构建参数覆盖；拉不到 Docker Hub 时见下方「镜像拉取失败排查」。

> 本项目的镜像构建不依赖原生编译，`npm ci --omit=dev` 只安装 Express。若本机没有 Docker daemon，仍可直接用 3.2 的 Node 方式运行。

#### 镜像拉取失败排查（国内 NAS / 飞牛 fnOS 常见）

典型报错：

```text
failed to resolve source metadata for docker.io/library/node:22-alpine:
dial tcp: lookup registry.linkease.net: Temporary failure in name resolution
```

这**不是项目代码问题**：构建停在第 2 步「解析基础镜像元数据」，`COPY` 和 `npm ci` 都还没执行。真正原因是 Docker daemon 配置的镜像加速域名解析不到。`registry.linkease.net:5443` 是飞牛论坛教程中 `kspeeder` 自建加速服务使用的**局域网主机名**，公网 DNS 本就不解析它，需要在 `/etc/hosts` 里指向运行 kspeeder 的设备 IP；如果没有部署 kspeeder，这条 mirror 就是失效的残留配置。

**① 先判断是「整体 DNS 故障」还是「只有加速域名失效」**（以下命令均为只读）：

```bash
cat /etc/resolv.conf
nslookup www.baidu.com           # 公网域名能否解析
nslookup registry.linkease.net   # 加速域名能否解析
docker info | grep -A4 "Registry Mirrors"
cat /etc/docker/daemon.json      # 只看，不要直接改
```

- 公网域名也解析不了 → NAS 的 DNS 配置有问题。在飞牛「设置 → 网络」把 DNS 改为 `223.5.5.5` / `119.29.29.29`，或临时改写 `/etc/resolv.conf`（可能被网络管理覆盖），再 `systemctl restart docker`。
- 只有 `registry.linkease.net` 解析不了 → 加速器失效，继续 ②。

**② 换一个可用的镜像仓库（推荐，走图形界面）**

飞牛桌面 → Docker → 镜像仓库 → 右上「仓库设置」→ 添加 `https://docker.1ms.run`（可用源可在 <https://status.1panel.top/status/docker> 查询）→ 选中并启用，同时停用 / 删除失效的 `registry.linkease.net:5443`。

> ⚠️ **不要用第三方脚本或命令直接覆写 `/etc/docker/daemon.json`**：飞牛在这份文件里保存了镜像 / 容器的存储路径（`data-root`），写错会导致原有镜像和容器「消失」。确需手改时先 `cp /etc/docker/daemon.json /etc/docker/daemon.json.bak`，只增删 `registry-mirrors` 数组，改完 `systemctl restart docker`。
>
> 如果确实部署过 `kspeeder`：先确认容器在运行（监听 5443），再在 NAS 的 `/etc/hosts` 加一行 `<kspeeder 设备 IP> registry.linkease.net`，加速即可恢复。

**③ 不想动 daemon 配置：从可达源拉取后打本地 tag 再构建**

带第三方前缀的镜像名不走 Docker Hub 的 mirror 规则：

```bash
docker pull docker.1ms.run/library/node:22-alpine
docker tag  docker.1ms.run/library/node:22-alpine node:22-alpine
DOCKER_BUILDKIT=0 docker build -t ckx/babyjournal:latest .
```

也可以直接用本项目的构建参数（`Dockerfile` 顶部的 `ARG`，默认值不变）：

```bash
docker build \
  --build-arg NODE_IMAGE=docker.1ms.run/library/node:22-alpine \
  --build-arg NPM_REGISTRY=https://registry.npmmirror.com \
  -t ckx/babyjournal:latest .

# compose 方式：写进 .env，或临时导出
NODE_IMAGE=docker.1ms.run/library/node:22-alpine \
NPM_REGISTRY=https://registry.npmmirror.com \
  docker compose up -d --build
```

`npm ci` 安装 Express 仍需访问 npm registry，国内网络建议同时指定 `NPM_REGISTRY=https://registry.npmmirror.com`。两个参数都是**构建期参数**，不会写进最终镜像的环境变量。

**④ 完全离线（NAS 无外网）**

在另一台能上网的机器上 `docker pull node:22-alpine && docker save node:22-alpine -o node22.tar`，把 tar 传到 NAS 后 `docker load -i node22.tar`；同时把已装好依赖的 `node_modules/` 拷入项目目录，并把 `deps` 阶段的 `RUN npm ci ...` 换成 `COPY node_modules ./node_modules`，即可零外网构建。若 NAS 上已装 Node 22，更简单的做法是直接用 [3.2](#32-本机启动) 的本机启动方式，完全跳过 Docker。

### 3.5 环境变量与数据目录

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；只想本机访问可设 `127.0.0.1` |
| `DATA_DIR` | `./data` | 数据库所在目录，不存在会自动创建 |
| `DB_PATH` | `<DATA_DIR>/baby-journal.db` | 指定单个数据库文件，优先级高于 `DATA_DIR` |
| `ADMIN_USERNAME` | `admin` | **仅首次启动且无管理员时生效** |
| `ADMIN_PASSWORD` | `123456` | 同上；设置后不再标记「待改密」 |
| `TZ` | 系统时区 | 建议 `Asia/Shanghai` |

`.env.example` 有完整注释可参考（本地直接 export 环境变量即可，Docker 请在 compose 的 `environment` 里设置）。

```
data/
├── baby-journal.db        # 主库（自动生成）
├── baby-journal.db-wal    # WAL 日志（运行中）
├── baby-journal.db-shm    # 共享内存（运行中）
└── who-source/*.csv       # WHO 原始百分位 CSV，溯源凭证，非运行时数据
```

> `data/*.db*` 与 `.ui-shots/`、`*.log`、`.env` 均已在 `.gitignore` / `.dockerignore` 中排除。`who-source` 是项目素材，请勿删除。

### 3.6 局域网访问与安全建议

- 同一局域网访问 `http://<主机 IP>:3000` 即可多人使用，每人用自己的账号登录。
- 若要外网访问，请加反向代理 + HTTPS + 访问控制，**不要直接把 3000 端口暴露到公网**。
- 所有接口都要求登录（静态页面除外）；Cookie 为 `HttpOnly + SameSite=Lax`；密码用 scrypt 加盐存储，数据库里没有明文密码。
- 备份导出文件是**明文 JSON**，含宝宝全部隐私记录，请自行妥善保管。

### 3.7 升级与旧库兼容

直接替换源码并重启即可，启动时会幂等执行：

- `CREATE TABLE IF NOT EXISTS` 建缺失的表；
- `migrateUsers` 给旧 `users` 表补 `is_admin` / `enabled` / `must_change_password` 列；
- `migrateDiaperPhoto` 给旧 `diaper_records` 表补 `photo` 列。

既有账号与记录**一行不动**。若旧库已有账号但没有管理员，会补建 `admin / 123456`；若 `admin` 这个名字已被占用，则只把该账号提升为管理员、**不重置它的密码**。已存在管理员时，启动什么都不做（改 `ADMIN_PASSWORD` 也不会覆盖已有账号）。

### 3.8 健康检查与日志

```bash
curl http://localhost:3000/api/health
# {"ok":true,"version":"1.0.0","dataDir":"..."}
```

启动日志会显示访问地址、数据目录、账号模式，以及初始管理员是否仍在使用默认密码的提醒；**不会打印任何密码**。

## 4. 使用指南

### 4.1 第一次使用的推荐顺序

1. **登录** `admin / 123456`，立刻到「设置与协作 → 账号安全」改掉初始密码。
2. **建家人账号**：侧栏「👥 用户管理」（或设置页下方的「用户管理 · 账号与权限」卡片）→ 新增账号，填昵称、初始密码，并按需勾选「系统管理员」、为每个宝宝分配档案角色。
3. **创建宝宝档案**：填昵称、出生日期、性别（决定用哪套 WHO 曲线）、可选预产期（早产儿校正月龄）、主题色、你的身份。创建者自动成为该档案的**档案管理员 owner**。
4. **开始记录**：从「今日概览」的快捷按钮，或进入各功能页填写表单。
5. **定期导出备份**：设置页「数据导出与备份 → 导出全部记录」，保存 JSON 文件。

> **系统管理员默认不属于任何宝宝档案**，不会自动看到既有隐私记录。需要查看时，在「用户管理」编辑自己的账号并分配档案权限；也可改完后到侧栏切换宝宝。
>
> **公开注册已关闭**：`/api/auth/register` 固定返回 403，任何人都不能自建账号。

### 4.2 账号与权限

两级权限，别混淆：

| 层级 | 取值 | 谁能改 | 作用范围 |
| --- | --- | --- | --- |
| 系统权限 | 系统管理员 / 普通账号 | 仅系统管理员 | 建号、改密、启停、删除账号、分配任何宝宝的档案角色 |
| 档案权限 | 档案管理员 owner / 可记录 editor / 只读 viewer | 仅系统管理员 | 单个宝宝的数据与导出 |

| 档案角色 | 能做什么 |
| --- | --- |
| 档案管理员 owner | 查看与增删改记录、编辑宝宝档案、导出全量数据、覆盖式恢复、删除整份档案 |
| 可记录 editor | 查看与增删改记录、追加导入 |
| 只读 viewer | 仅查看（适合长辈）；仍可新建自己的宝宝档案并从备份恢复 |

账号生命周期要点：

- 管理员可编辑昵称、系统权限、启用 / 停用、重置密码、逐个宝宝分配角色；停用、改密、重置密码会**立即清除该账号的会话**。
- 删除账号**不删历史记录**：12 类记录的 `user_id` 全部转给执行删除的管理员；若被删账号是某档案唯一的 owner，会把剩余成员提为 owner。
- 保护规则：至少保留一名可用系统管理员；不能停用 / 降级 / 删除自己；每个宝宝至少保留一名 owner；失败整体事务回滚。
- 任意登录用户可在「设置与协作 → 账号安全」修改自己的密码。
- 两个管理入口（侧栏「用户管理」页 + 设置页内嵌卡片）调用同一组接口，功能完全一致；普通账号在设置页只会看到说明文字，不会出现管理按钮。

### 4.3 宝宝档案与切换

- 侧栏顶部是宝宝切换胶囊，点「＋」可新建档案；切换宝宝时整站主题色会跟着变。
- 「设置与协作 → 宝宝档案」可修改昵称、生日、性别、预产期、主题色、备注；**仅 owner 可改**。
- 「照护者与权限」是只读名单，展示当前档案下所有成员的角色与身份；权限改动请到「用户管理」。
- 每位成员看到的记录相同，但写入权限按角色区分；每条记录都保存记录人昵称。

### 4.4 各页面怎么用

**🏠 今日概览** — 顶部四个快捷按钮（记喂养 / 记睡眠 / 记便便 / 记童言）直接打开对应表单；切换日期可回看任意一天；下方「成长速览」「接种提醒」给出月龄、最近测量与待登记剂次概览。

**🍼 喂养记录** — 选类型后表单会按条件展开：配方奶 / 母乳瓶喂 / 辅食显示「奶量」，亲喂显示「时长」，亲喂可选左右侧，辅食可填食物名。勾选「首次引入过敏原」后额外出现过敏原与反应等级字段，保存时会**自动写入一条过敏原引入台账**，右侧时间线同步展示。

**😴 睡眠记录** — 填「开始 / 结束时间」会自动计算时长；夜间睡眠可填夜醒次数与质量；单独的「夜醒」类型用于标记中途醒来。

**🚽 大小便** — 按小便 / 大便展开不同字段（尿量 / 颜色 / 性状 / 便量）。底部可「选择照片」：图片会在浏览器里等比压缩（最长边 1280、JPEG 质量 0.78）后存入数据库，表单出现预览、可移除或换图；时间线显示缩略图与「📷 有照片」标记，点击看大图，编辑记录时可保留或删掉原照片。灰白 / 带血丝会自动加「建议关注」标签。

**🌕 黄疸观察** — 填经皮胆红素值、部位、程度、是否消退；有两条以上数值记录时，页面按首次与最新数值给出升降趋势提示（只按已登记数值比较，不构成医学判断）。

**📈 生长曲线** — 左侧录入体重 / 身长 / 头围（可只填一项），自动按当天月龄对照 WHO；右侧是百分位曲线 SVG 与数据表。可切换指标（体重 / 身高 / 头围）与量程（0–12 / 24 / 36 / 60 月）。偏离标红规则见 [第 6 节](#6-who-生长标准与偏离判定)。

**⭐ 发育里程碑** — 上半部是 13 项预设里程碑的对照表：点格子上的「记录达成」选日期即可，已达成格子显示月龄与「窗口内 / 偏早 / 偏晚」判定；顶部四张统计卡给出已达成数、当前月龄、本月窗口内项数、超窗口未达成项数。下半部是**自定义里程碑**：点「＋ 添加自定义里程碑」，填名称（≤30 字）、达成日期、备注，即可记录「第一次自己拿勺子」这类对照表之外的瞬间；每条可修改、删除。自定义项**不参与**月龄窗口判定，也不影响上方统计与儿保提示，但会随备份导出 / 导入完整保留；只读成员只能查看。

**🩺 医疗档案** — 四个页签：
- **接种表**：按国家免疫规划程序（2021 版）整理 17 组疫苗、逐剂次列出参考月龄，点「登记」写入实际接种日期、门诊、批号、反应；「未登记」只表示系统里没记录，**不等于漏种**，一律以预防接种证为准。
- **儿保体检**：机构、月龄（可自动推算）、体重 / 身长 / 头围、结论与医嘱。
- **用药记录**：药品、剂量、起止日期、原因。
- **过敏史**：过敏原、反应、严重程度、首次发现日期、当前状态。

**💬 童言童语** — 建议一字不改地记下原话（包括发音和语法错误），并写清当时语境：在哪、和谁、发生了什么。支持按关键词搜索；这部分数据导出时完整保留。

**⚙️ 设置与协作** — 从上到下的区块：用户管理（管理员）、宝宝档案、删除宝宝档案（危险区）、数据导出与备份、照护者与权限、账号安全、数据与来源说明。

**👥 用户管理** — 账号表格显示用户名、昵称、系统权限、启停状态与各档案角色；「新增账号」弹窗里可以一步完成建号 + 分配权限；编辑弹窗可改昵称、系统权限、启停、重置密码、逐个宝宝角色；删除前有二次确认。

### 4.5 主题色

「设置与协作 → 宝宝档案 → 主题色」提供 5 套配色：蜜桃粉（默认）、暖杏黄、薄荷绿、薰衣紫、柠檬黄。

- **点色卡立即预览**，整站同步变化（主按钮、选中导航、宝宝切换胶囊、标签页、Logo、输入框焦点环、页面渐变背景）；点「保存档案」才写入数据库。
- 主题**跟随当前宝宝**：切换宝宝自动换色，刷新不闪回默认色（`localStorage` 记住上次主题）。
- 主题色存在 `babies.color`，随 v2 备份导出、换机导入自动恢复；后端按白名单校验，非法值整条 PATCH 返回 400。

### 4.6 数据导出、备份与换机迁移

**导出**：设置与协作 → 数据导出与备份 → 「导出全部记录」（仅档案管理员可见），得到 `宝宝名-成长记录-日期.json`。内容包含宝宝档案配置、12 类记录、照护者名单（角色 / 身份）、每条记录的原始记录人、WHO 数据来源说明；**不含任何账号密码、密码哈希或会话**，可放心归档。

**导入恢复**：同一卡片点「📥 导入配置并恢复」，选择 JSON → 预览宝宝信息、导出时间、各模块记录数 → 选择恢复方式。没有宝宝档案时，空状态页也提供「从备份文件恢复」入口。

| 方式 | 适用场景 | 行为 | 权限 |
| --- | --- | --- | --- |
| **新建宝宝档案恢复**（默认） | 换机部署、整份归档还原 | 用备份配置新建宝宝并恢复全部记录；**不影响现有任何数据**，当前账号自动成为 owner | 任何已登录账号 |
| **覆盖当前宝宝** | 备份回滚、纠正错误导入 | 清空目标宝宝全部现有记录，同步改写档案配置后写入；需勾选二次确认 | owner |
| **追加到当前宝宝** | 两台设备合并、补录遗漏 | 保留现有记录，只追加备份内容；按业务字段生成指纹，内容相同的自动跳过，重复导入不会翻倍 | owner / editor |

**换机完整步骤**：

1. 旧机器：导出 JSON 并保存好。
2. 新机器：按 [3.2](#32-本机启动) 装好并启动，用初始管理员 `admin` 登录。
3. 「用户管理」→ 新增账号：**用户名务必与原机相同**（备份按用户名还原记录人与协作关系），家人账号也一并建好。
4. 退出，用刚建好的账号登录；此时没有宝宝档案，页面直接显示「📥 从备份文件恢复（换机迁移）」。
5. 选择 JSON → 预览 → 「新建宝宝档案恢复」→ 开始恢复。
6. 完成弹窗列出写入条数、恢复的协作成员与待补账号；关闭后直接进入恢复后的今日概览。

不需要预先建档、不需要拷贝数据库文件、不需要改配置。**备份不含密码，账号必须由管理员先建好**；本机不存在的账号不会被伪造，会列在恢复结果里提示补建。若嫌逐个建号麻烦，也可以直接冷备份整个 `data/` 目录，那样账号密码会原样保留。

### 4.7 删除宝宝档案

「设置与协作 → 删除宝宝档案」是红色危险区，仅该档案的 owner 或系统管理员可见。点击后需**手动输入宝宝昵称**二次确认，后端再校验一次，然后在一个事务里清除该档案下全部 12 类记录（含照片）、照护者关系与档案本身，返回清理条数。删除后自动切换到其他档案；若无档案则回到建档引导页。**不可撤销**，执行前建议先导出一份备份。

### 4.8 清空全部数据、恢复初始状态

需要把系统恢复到「刚装好」的状态（例如清理测试数据）时：

1. **先完整备份**：停掉服务，复制 `data/baby-journal.db`、`-wal`、`-shm` 三个文件到安全位置（不要只复制 `.db`，WAL 里可能有未合并的数据）。
2. 删除这三个文件（保留 `data/who-source/`）。
3. 重新启动服务：会自动建库建表，并创建唯一的初始管理员 `admin / 123456`（`is_admin=1`、`must_change_password=1`）。
4. 用初始密码登录，确认「用户管理」只有 admin 一个账号、没有任何宝宝档案、所有记录为空，然后立即改密码。

> 这会**永久删除所有账号、宝宝与记录**，操作前务必确认备份可用。历史测试截图在 `.ui-shots/`（运行 `npm run ui:check` 才会生成），运行日志为 `*.log`，均可单独清理。

## 5. 备份文件格式与安全边界

导出文件是 v2 JSON（早期 v1 文件也可直接导入）：

```json
{
  "app": "baby-journal",
  "schemaVersion": 2,
  "exportedAt": "2026-11-09T02:46:32.640Z",
  "whoSource": "WHO Child Growth Standards (2006) ...",
  "scope": "baby",
  "baby": { "name": "小芽", "birth_date": "2025-05-10", "gender": "female", "due_date": null, "color": "pink", "note": null },
  "members": [ { "username": "mama", "display_name": "妈妈", "role": "owner", "relation": "妈妈" } ],
  "records": {
    "feeding": [{ "occurred_at": "...", "type": "formula", "amount_ml": 120 }],
    "milestone": [{ "milestone_key": "custom:第一次自己拿勺子", "achieved_at": "...", "note": "..." }],
    "growth": [], "quote": []
  }
}
```

- `baby`：档案配置（昵称、生日、性别、预产期、主题色、备注）。
- `members`：照护者用户名、昵称、角色、身份；导入时按用户名匹配本机已有账号重建关系。
- `records`：12 个集合，字段名与数据库列一致；照片以 `data:image/jpeg;base64,...` 直接存在记录里，因此无需额外上传目录，备份天然携带。
- 自定义里程碑的 `milestone_key` 以 `custom:` 前缀保存名称，与预设里程碑共存、互不干扰。

**校验与安全边界**：

- 导入前逐条按**字段白名单、必填项、枚举值**校验，限制单集合 5 万条、总计 20 万条；任何一条不合法就整体拒绝，不会留下半成品。写入全过程在一个 SQLite 事务里，失败自动回滚。
- 请求体上限：导入接口 **25 MB**（前端也会先检查文件大小）、含照片的记录接口 **8 MB**、其余接口 **1 MB**；照片字段另有 300 万字符上限与 `data:image` 格式校验，非法数据直接 400。
- 照片数量特别多时备份会变大，仍受 25 MB 导入上限约束，建议分批导出。
- **不恢复账号密码**：按用户名匹配本机已有账号；找不到的记录人归入当前操作账号，原始昵称仍完整保存在备份里。照护者名单属于账号权限，只有系统管理员或该档案 owner 能通过导入改写成员关系。
- `replace` 不可撤销，执行前建议先导出一份当前数据。
- **冷备份**：先停服务再复制三个文件；迁移时把 `data/` 整目录放到新机器同一位置，或设置 `DATA_DIR` / `DB_PATH` 指向它。

## 6. WHO 生长标准与偏离判定

**数据来源（非编造值）**：`src/data/who-lms.json` 是 WHO Child Growth Standards (2006) 的 0–1856 天 LMS 展开表，覆盖 0–60 月龄、男女、体重 / 身长身高 / 头围。转录链路：WHO 官方 expanded tables → `who-growth-standards` npm 包（数据表由 `cdn.who.int` 官方 Excel 生成）→ 本项目按 `365.25/12` 天折算为月龄 L/M/S 数组。`data/who-source/` 另存了 CDC 发布的 WHO 0–24 月百分位 CSV 用于独立交叉校验：0 月完全一致，12/24 月中位数误差 < 0.1%，个别月龄因天数取整差异 < 0.5%，远小于测量误差。原始 CSV 只覆盖 0–24 月，之后数据来自 WHO 官方按天展开表。

**计算**：`z = ((X/M)^L − 1)/(L·S)`（L≈0 时用 `ln(X/M)/S`），再由正态分布换算百分位；任意百分位线用 `X = M(1+L·S·z)^(1/L)` 生成。前后端共用 `public/js/growth.js`，结果一致。

**标红规则**（家庭趋势观察，不是诊断）：

- 单次测量低于 P3 或高于 P97 → 红色；
- 与上一条同指标记录相比 z 值下降 ≥ 1.0（约跨越两条主百分位带）→ 红色，提示曲线明显下移；
- z 值下降 ≥ 0.67 → 黄色，提示持续观察。

**重要边界**：

- 在参考范围内不代表没问题，超出范围也可能是正常个体；判断必须由儿保医生结合胎龄、喂养与病史做出。
- 2 岁前量「身长」（躺），2 岁后量「身高」（站），两者约差 0.7 cm，WHO 表在 24 月处本身存在该切换。
- 填写预产期后，早产宝宝按校正月龄对照曲线。
- 里程碑月龄窗口为国内儿保常用参考区间，疫苗程序参考《国家免疫规划疫苗儿童免疫程序（2021 版）》整理；**「未登记」不等于「漏种」**，一律以预防接种证与接种门诊为准。
